# LyFlow ly_probe rule source

LyFlow compiles a conservative subset of Suricata rules into the JSON format
consumed by ly_probe's `servicePlugin`.

## Generate once

```bash
cd /opt/lyflow/src
go run ./server/cmd/rulecompiler \
  -once \
  -source rules/lyprobe/source \
  -output rules/lyprobe/threat.json \
  -manifest rules/lyprobe/manifest.json
```

## Keep rules fresh

```bash
/opt/lyflow/bin/lyflow-rulecompiler \
  -source /var/lib/lyflow/rules/source \
  -output /opt/lyflow/fp-patterns/threat.json \
  -manifest /opt/lyflow/fp-patterns/manifest.json \
  -interval 2s \
  -reload-command 'systemctl restart lyprobe'
```

The compiler polls the source, validates the generated JSON and regexes, writes
`threat.json` atomically, and only then invokes the reload command. On a failed
compile the previous `threat.json` is kept and the sensor is not reloaded.

The current ly_probe upstream ignores `SIGHUP` and has no built-in rule reload,
so the default hook restarts `lyprobe`. A patched zero-downtime reload can be
substituted by changing `-reload-command` without touching the compiler.

## Required ly_probe template

The service plugin is only enabled when the NetFlow v9 template references its
fields. The template must include `%PROTOCOL` so protocol filtering in
`threat.json` works, plus at least one `%THREAT_*` field:

```text
%PROTOCOL %IPV4_SRC_ADDR %IPV4_DST_ADDR %L4_SRC_PORT %L4_DST_PORT %THREAT_TYPE %THREAT_NAME %THREAT_VERS
```

If `%PROTOCOL` is omitted, ly_probe sets `ignoreProtocol=1` and rules with
`"protocol":"tcp"`/`"udp"` will never match.

## Conversion scope

Converted:

- one `content` or one simple `pcre` per rule
- HTTP URI/header/body sticky buffers
- TLS SNI
- exact DNS query names (encoded to DNS label regex)
- `nocase` and PCRE `i` flag

Left to Suricata:

- multiple content matches
- `flowbits`, byte tests/jumps, thresholds, datasets
- complex PCRE unsupported by Go's RE2 validator
- rules whose buffer/port semantics cannot be represented safely

`manifest.json` records every skipped rule with its SID and reason.

## Runtime layout

Install generated files next to ly_probe's other fingerprints:

```text
/opt/lyflow/fp-patterns/
├── service.json
├── device.json
├── os.json
├── midware.json
├── threat.json      # generated by LyFlow
└── manifest.json    # generated by LyFlow
```

The service plugin searches `./fp-patterns` first, so run ly_probe with
`WorkingDirectory=/opt/lyflow` or install the directory in one of its search
paths.
