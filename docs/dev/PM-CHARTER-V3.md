# LyFlow v3 产品章程 · 门禁边界与专家分派

> 角色：产品经理（PM）
> 依据：《LyFlow 商业级 XDR + RASP 优化与风险修补方案 v1.0》（架构专家）
> 版本：3.0 · 2026-10-29
> 效力：本文件是 v3 迭代的任务边界。架构方案中的门禁（Gate）不可被实现方单方面降低；
> 任何"看起来更好但证据不足"的改动都不得越过门禁。

---

## 1. 产品判断（PM 视角）

### 1.1 这个产品到底是什么

LyFlow 不是"告警聚合大屏"，而是**证据链工作台**：把网络、主机、应用三侧的原始信号，
变成一条可追溯、可解释、可闭环、可复盘的处置链路。

因此产品的核心竞争力不是规则数量，也不是图表炫酷程度，而是三件事：

1. **敢信**：每个数字都能回答"从哪来、什么时间窗、样本多少、缺了什么"。
2. **敢判**：每条 Incident 都能回答"为什么关联、证据多强、有无反证"。
3. **敢动**：每个处置动作都能回答"谁批的、影响范围、如何回滚"。

### 1.2 目标用户与真实场景

| 角色 | 场景 | 最痛的点 | 产品必须给 |
|---|---|---|---|
| 一线值守 | 夜班盯屏、快速分诊 | 告警太多、真假难辨 | 排序可信、噪声可抑制、一键下钻 |
| 事件响应 | 攻击链复盘、止损 | 证据散落、时间对不齐 | 统一时间线、实体图谱、证据分级 |
| 安全架构 | 能力评估、方案优化 | 不知道系统到底覆盖了什么 | 覆盖/质量/留存的可核对视图 |
| 运维/交付 | 部署、升级、排障 | 黑盒、无健康视图 | 组件健康、采集可见性、可回滚 |

### 1.3 三条产品红线

1. **不伪造**：缺失不补 0，未读取不显示绿色，未验证不称"已阻断"。
2. **不混淆**：已配置 / 已启动 / 有数据 / 在检测 / 在阻断，是五种状态，不是一个绿点。
3. **不堆砌**：新增规则、新增图表、新增指标，必须能被现有证据链解释，否则不做。

### 1.4 与架构方案的关系

架构方案解决"**对不对**"（数据可信、链路可靠、关联可解释）。
PM 补充"**有没有用**"（谁在什么场景下用它做决定）。

两者冲突时，以架构门禁为准；门禁之外，以用户任务完成度为准。

## 2. 门禁边界（Gate）

以下 Gate 来自架构方案，**只允许加严，不允许放宽**。每个 Gate 未通过，不得进入下一阶段
对外宣称"已完成"。

### Gate 0 — 基线与复核

- 复核分支、部署、数据库 schema、运行时指标。
- 每项风险（R-01 ~ R-14）必须有：真实证据、负责人、验收方式。
- 产出：代码路径清单、运行基线、风险确认表、测试计划。

### Gate 1 — 数据可信与可靠性（P0）

- EventV2 缺失语义：`null/unknown` 与真实 `0` 必须区分。
- 幂等键使用稳定来源 ID 或规范化 payload hash，并版本化。
- 投影失败可重试、可进 DLQ、可重放，不静默丢失。
- 留存 30 天承诺必须用**真实逐日可查询数据**验证，不能用 TTL 配置替代。
- 时间源必须可观测；手动时间源不得显示为已同步。
- 租户绑定负向测试通过。

### Gate 2 — 采集可见性（P0）

- 计数器口径统一（累计/区间），重启与回绕可处理。
- 健康状态机：healthy / degraded / partial / failed，附 reason、since、last_success_at。
- 降级时 UI/API 显示真实 backend 与受影响能力。
- 端到端丢失率在分母可信时才计算，否则显示 unknown。

### Gate 3 — 关联与 Incident（P0）

- 弱证据（同 IP、同网段、同规则名）不得单独形成高置信度横向移动结论。
- 每条 Incident 有：代表性证据、关联边、时间线、受影响实体、置信度解释。
- 同活动可合并，无因果关系不得强行合并。
- 关联延迟/内存有预算，超限标记 partial correlation。

### Gate 4 — 规则与行为基线（P1）

- 规则有 ID/版本/最低字段/正负样本/误报说明。
- 行为基线有版本、样本范围、漂移监控、审批、回滚。
- 新算法先 shadow，与 baseline 对比误报/漏报/资源消耗后再启用。

### Gate 5 — RASP 能力（P0/P1）

- 五态分离：未安装 / 已安装 / 采集中 / 检测中 / 阻断中。
- monitor 模式不得显示"已阻断"。
- 阻断策略有 dry-run、fail-open/closed、旁路、紧急开关、审计。
- 阻断计数可与端侧日志对账。

### Gate 6 — 商业化与运营（P1）

- RBAC、多租户、升级/回滚、备份恢复、SLO。
- 发布流程、兼容矩阵、恢复演练、运维手册全部可执行。

## 3. 专家分派（Workstreams）

每个工作流只改自己的范围，接口变更必须同步契约与调用方。

### WS-1 前端架构与设计系统（Frontend / Design System）

- 交付：v3 "Signal Grid" 设计令牌、共享组件、外壳、响应式与可访问性。
- 门禁：状态不可仅靠颜色；未知态视觉上与健康态可区分；`prefers-reduced-motion` 生效。
- 验收：设计契约文档 + 组件测试 + 375/768/1280 三档截图。

### WS-2 数据可信度（Data Trust）

- 交付：字段完整率、端口未知率、按来源质量、留存跨度、时间质量视图。
- 门禁：Gate 1 的语义要求；空样本显示"—"。
- 验收：纯函数单测覆盖缺失/零值/空样本/加权口径。

### WS-3 态势与调查工作台（Situation / Investigation）

- 交付：多时间窗总览、ATT&CK 阶段、Top 规则/热源、处置队列、实时流。
- 门禁：所有指标标注窗口与口径；不使用不可解释的综合评分。
- 验收：每个卡片可下钻到原始事件或 Incident。

### WS-4 采集与 Agent（Capture / Agent）

- 交付：可见性指标合同、健康状态机、丢包对账。
- 门禁：Gate 2。
- 验收：压力回放报告 + 降级告警。

### WS-5 XDR 关联与 Incident（Correlation）

- 交付：候选索引、证据分级、根因聚合、评分解释。
- 门禁：Gate 3。
- 验收：弱证据反例测试、性能预算、shadow 对比。

### WS-6 RASP（Runtime Protection）

- 交付：能力矩阵、runtime schema、检测/阻断分级。
- 门禁：Gate 5。
- 验收：端侧正反样本 + 性能开销。

### WS-7 平台交付与运维（Platform / Delivery）

- 交付：ESXi 虚机、Docker 栈、健康检查、备份、升级/回滚手册。
- 门禁：Gate 6；破坏性操作前必须 dry-run + 人工确认。
- 验收：全新环境一键部署 + 重启恢复 + 回滚演练。

### WS-8 质量与验收（QA / Acceptance）

- 交付：验收脚本、测试矩阵、缺陷单、验收报告。
- 门禁：所有 Gate 的验收项逐条留痕。
- 验收：任何"通过"必须附命令、输出、时间、环境。

## 6. 风险与回滚

- 部署为**新建虚机 + 新建栈**，不触碰 10.1.18.198 现有环境。
- 若资源不足，优先降配新虚机，不关闭他人实验虚机。
- 所有破坏性命令先 dry-run；数据卷删除必须人工确认。
- 回滚：删除新虚机与新数据卷即可回到部署前状态。

## 7. v4 信息架构决策（PM 裁定）

### 7.1 原则

1. 一个页面只回答一个运营问题；答不了的页面不保留。
2. 合并同一数据源的重复入口，避免"同一件事三个页面"。
3. 数据不足的展示面直接砍掉，不用空图占位。
4. 旧链接必须继续可用，通过重定向而不是保留旧页面。

### 7.2 保留并重做的 8 个作业面

| 作业面 | 路由 | 回答的问题 |
|---|---|---|
| 态势总览 | /overview | 现在最该关注什么 |
| 攻击链处置 | /incidents | 这条链证据够不够、怎么闭环 |
| 事件检索 | /events | 某条告警的原始事实是什么 |
| 检测面 | /threats | 流量/主机/应用各自检出了什么 |
| 资产运维 | /assets | 哪些资产在采集、能力是否齐全 |
| 数据与健康 | /health | 数据可不可信、引擎与组件是否正常 |
| 规则中心 | /rules | 规则从哪来、版本是否最新 |
| 系统管理 | /settings | 平台参数、账户与安装 |

### 7.3 砍掉与合并

| 旧页面 | 处置 | 理由 |
|---|---|---|
| 全球态势 | 砍掉，重定向 /overview | 真实数据只有少量公网 IP，地图不构成运营决策 |
| 证据库 | 并入 /incidents | 证据只在 Incident 上下文里有意义 |
| 响应处置 | 并入 /incidents 与 /settings | 动作必须挂在具体事件或策略上 |
| 时间线 | 并入 /incidents | 与阶段时间线重复 |
| 引擎健康 | 并入 /health | 健康是数据可信的一部分 |
| 数据质量 | 并入 /health | 同上 |
| 账户管理 | 并入 /settings | 低频管理动作 |
| 安装配置 | 并入 /assets 与 /settings | 安装是资产接入的一部分 |

### 7.4 新增能力

- 资产运维：能力矩阵、心跳延迟、单机引擎健康、重命名/删除、安装与卸载命令。
- 数据与健康：五元组完整率、端口未知率、按来源质量、可查询跨度、组件健康。
- 检测面：三类检测合并为同一页签，统一筛选与详情抽屉。
- 顶栏"平台真实状态"：组件健康、在线 Agent、时间源与偏移，读取失败显示未知。
