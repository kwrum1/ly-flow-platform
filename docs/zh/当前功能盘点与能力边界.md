# 当前功能盘点与能力边界

> 更新日期：2026-08-02
> 判断原则：只把当前代码、正式 Compose、GitHub 原生构建或实际验收能够证明的能力写为已实现。

## 1. 产品结论

当前版本是可安装的单机 XDR 安全态势感知产品：服务端可通过本机镜像口接收流量，主机 Agent 可上报多类安全遥测，安全引擎和 XDR 可消费这些事件并形成 ATT&CK 攻击链与 Incident，控制台可完成查询、分诊和处置。

它仍不是完成全部政企认证的商业终态。CentOS 7 长稳、ARM 实机、真实业务 RASP 兼容、检测效果量化、多节点高可用和自动响应仍有明确边界。

## 3. 正式默认容器

正式栈固定为 9 个容器：`ly-vis`、`ly-server`、`agent-center`、`ly-local-mirror`、`ly-suricata-sensor`、`ly-security-engine`、`postgres`、`clickhouse`、`redis`。

这些组件分别承担入口、业务、Agent 管理、采集、IDS、统一检测、事务存储、分析存储和事件总线。继续硬合并会扩大故障影响并降低升级、隔离和定位能力，因此当前不合并。

以下组件不属于默认生产栈：

- `ly-engine-lab`：历史实验壳，正式能力不依赖它。
- 容器 Agent：只用于 QA 与联调。
- 原 legacy DPI 已移除；旧 `flows:raw` 数据仅由统一安全引擎和 LyFlow 探针处理。
- Java RASP：实验能力，不作为当前生产承诺。

## 4. 数据边界

- PostgreSQL：账号、资产、Agent、规则、告警、攻击链、Incident、处置和审计。
- ClickHouse：长期会话与高容量分析事件。
- Redis：实时事件总线、短期缓冲和控制健康流，不是正式数据仓库。
- Agent 本地加密 spool：平台临时不可达时缓冲并重放，不替代服务端存储。

## 5. 规则与特征库边界

正式构建会从公网重新获取五个流量规则源并编译，不使用历史规则缓存。运行中的规则中心也能执行在线更新和热生效。

“上游最新”不等于“全部规则可直接运行”。Suricata/Snort 等规则方言和版本存在差异，不兼容单条规则会被隔离并展示原因；可兼容规则继续构建。Wazuh、YARA、RASP 和 Runtime 各自使用对应适配器与规则格式，不能用一个规则数量代表全部检测能力。

## 6. 当前不能扩大承诺的事项

1. 只有单机部署，不承诺多节点 HA 或异地容灾。
2. ARM64 服务端和 Agent 已完成云端原生构建，尚缺指定 ARM 服务器与网卡的长期现场认证。
3. Linux Agent 面向 CentOS 7/Linux 3.10 设计，仍需独立目标机 72 小时稳定性和性能证据。
4. Python RASP protect 已实现，但没有真实业务框架白名单前不承诺对所有应用直接阻断；Java RASP 仍为实验能力。
5. XDR 当前提供人工处置和建议，不自动隔离主机或封禁网络。
6. 检测主链路可用不等于检测质量已经量化，仍需持续恶意/正常 corpus、误报率、召回率和吞吐基线。
7. 全量会话是长期语义会话，不是原始全包取证。
