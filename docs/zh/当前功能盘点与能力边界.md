# 当前功能盘点与能力边界

> 盘点基线：`takeover/20260730`，提交 `c93d960`，2026-07-30。
> 判定方法：代码实现 + 路由契约 + 测试/QA + `10.1.18.100` 当前运行验收。
> 状态含义：生产已验收、已实现但有限制、QA/兼容、未形成生产承诺。

## 一、生产已验收主链路

### 1. 平台部署与基础设施

- 默认单机 Compose 栈包含 PostgreSQL、Redis、ClickHouse、`ly-server`、`agent-center`、`ly-security-engine`、`ly-engine-lab`、`ly-local-mirror` 和 `ly-vis`，当前 9 个服务健康运行。
- HTTPS 443 为统一用户入口，API 和 WebSocket 经同源代理访问。
- 离线包具有镜像 digest pin、外置信任根验签、安装失败回滚、初始管理员随机凭据和首次改密机制。
- Redis 使用 ACL，健康检查要求精确 `PONG`；宿主机持久化 `vm.overcommit_memory=1`。

### 2. 认证、路由与身份

- 用户登录、注销、会话、首次强制改密、用户管理和角色路由策略已经实现。
- 服务端采用 deny-by-default 路由注册表，当前挂载 116 条路径。
- Agent 使用短时、一次性、绑定 Agent ID 的 enrollment token 注册；后续心跳、配置、事件和快照使用持久 Agent 凭据。
- Agent 身份支持签发、轮换、撤销、恢复和凭据审计的底层状态机。

### 3. 无容器 Linux Agent

- Linux amd64 Agent 可构建为 `CGO_ENABLED=0`、`GOAMD64=v1` 的静态 ELF，不依赖现场 glibc 或 libpcap。
- Linux 3.10/CentOS 7 目标使用 AF_PACKET/TPACKET 抓包，运行监控无法使用 eBPF 时回退 auditd。
- 已实现心跳、配置拉取、任务结果、资产快照、接口/进程/性能采集、本地加密 spool、流量采集和 HTTP 凭据上报。
- 当前接盘环境中的 systemd Agent 已注册、持续心跳、资产快照成功，重启次数为 0。

### 4. 流量观测和检测

- 外部 Agent 与 `ly-local-mirror` 复用流量采集能力；local-mirror 可显式选择 `lo` 做单机验收，生产旁路应使用实际镜像网卡。
- 支持 TCP/UDP 基础解析、语义 flow/session、会话持久化、关键词查询和流量来源标识。
- Agent 侧包含 Nmap 风格 SYN 扫描聚合；统一安全引擎消费 `telemetry:traffic` 并输出 DPI 类告警。
- Linux 静态构建当前只接受 `tcp`、`udp`、`tcp or udp` 三种管理面 BPF 表达式，未知表达式拒绝执行。

### 5. 统一检测、事件和 XDR

- `ly-security-engine` 统一消费 traffic、runtime、RASP 和 log-audit 遥测，输出分类告警。
- 服务端将多源告警标准化并持久化，提供统一事件统计、列表和检索接口。
- XDR 支持按实体、阶段、证据和时间窗口形成关联链；Incident 生命周期、状态迁移、幂等、审计和 legacy cutover 已有持久化实现。
- 前端具备总览、事件、Incident、时间线、XDR、资产、流量/运行时/RASP 威胁、Trace、规则、用户、安装配置和控制中心等当前路由。

### 6. 规则与交付

- 规则源、库存、统计、测试、编译预览、签名 candidate、激活、热重载、版本和回滚链路已实现。
- 发布流程包含固定工具链、容器烟雾测试、来源证据、SBOM/扫描记录和 amd64 离线资产。

## 二、已实现但不能扩大承诺的能力

| 能力 | 当前事实 | 边界 |
|---|---|---|
| Agent 远端传输 | 流量、运行时、资产主链路有 Agent 凭据 HTTP 接口 | 少量 RASP 健康和兼容路径仍含 Redis 直连；远端现场不得以开放 Redis 为前提 |
| ClickHouse | 有双写、对账、watermark、回压、读切换和回滚控制 | 未在目标数据集完成 reconcile 和 read-switch 前，PostgreSQL/当前 reader 仍是权威 |
| RASP | Python 检测与桥接存在；Java 有实验实现 | Java 为 experimental、monitor-only、allowlist-only；不承诺生产阻断 |
| 响应 | 有 response candidates、policy 和 advisory 查询 | 候选当前只读，enforcement endpoint 未实现 |
| RBAC | 后端支持 admin/analyst/viewer 路由角色 | 当前主要前端业务路由全部限制为 admin，尚未形成角色化操作界面 |
| gRPC Agent Center | 服务和身份认证代码存在 | 当前真实宿主机 Agent 主控制面使用 HTTP；不得同时宣称 gRPC 为已验收现场主路径 |
| arm64 | 构建逻辑和静态 Agent 路径具备基础 | 当前自动发布和现场验收是 amd64，arm64 不具备发布等价性证据 |
| 高可用 | 组件可独立运行并有可靠性机制 | 当前交付是单机 Compose，不承诺多节点 HA、跨站容灾或水平扩展 |
| 全量取证 | 有语义流量、会话和有限 retention | 产品目标不是全包留存、全协议解析或法证级零丢失 |

## 三、QA、兼容和历史能力

- `container-agent` 和 `suricata-profile` 只用于 QA、联调和发布验收，不是政企现场 Agent 安装方式。
- `legacy-dpi` 中的 `ly-dpi-engine` 消费旧 `flows:raw`，仅用于迁移、结果对比和回归；不得与统一引擎长期并行。
- `ly-engine-lab` 用于外部引擎运行状态和受控验收，不代表所有第三方引擎都进入默认生产承诺。
- 前端 `layout/nav-config.js` 等旧导航配置不是当前 router 权威，契约中标记为 remove 的页面不算已实现页面。

## 四、当前明确缺口

1. 远端 Agent 仍需彻底去除 Redis 网络依赖，并在隔离的 CentOS 7/Linux 3.10 主机完成端到端验收。
2. Agent 安装、升级、回滚、证书信任、令牌签发和批量运维尚未形成完整现场工作流。
3. ClickHouse 迁移控制已实现，但正式数据对账、观察期和权威读切换未完成。
4. 多数 runtime-only 配置变更需要统一持久化、重启恢复和审计语义。
5. 检测效果缺少持续的真实流量 corpus、误报率/召回率指标和版本准入门槛。
6. 响应处置边界尚未由产品负责人确定；当前只能给建议，不能执行阻断。
7. 前端角色模型、错误页和旧导航代码仍需收敛。
8. 当前 Agent 全量测试有一项既存 Suricata golden replay 漂移，需要重新固定基线或修正归一化逻辑。

## 五、不应对外宣称

- 不宣称自动阻断、生产级 Java RASP、零误报、零丢失或全协议识别。
- 不宣称 arm64 与 amd64 等价交付。
- 不宣称 Redis 是正式数据权威，也不要求外部 Agent 直连 Redis。
- 不宣称容器 Agent、legacy DPI 或实验引擎属于默认生产组件。
- 不宣称单机 Compose 已具备 HA、容灾或大规模多租户能力。
