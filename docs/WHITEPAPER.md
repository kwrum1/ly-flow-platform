# 流影白皮书

## 摘要

流影是一套以 Agent、流量镜像、运行时、RASP、日志审计和 XDR 关联为核心的安全运营平台。它面向需要快速落地、可离线交付、可解释告警的场景，强调三点：真实上下文、低噪声和可验收安装。

与传统单点安全设备不同，流影把网络、主机、应用与规则运营放在同一条事件链路里：采集层产生遥测，安全引擎执行规则，服务端持久化并关联，前端按运营视角展示资产、威胁、攻击链和处置建议。

## 1. 背景

安全运营常见问题包括：

- Agent 在线状态和资产状态不一致。
- 流量告警噪声过高，识别类事件被当成威胁。
- 扫描、登录、上传、运行时、RASP 等事件分散在不同系统。
- 攻击链缺少证据时间和阶段归属。
- 新环境部署依赖复杂，验收重复成本高。

流影的产品方向是：把关键安全行为变成统一、可关联、可查询的事件，而不是追求全协议、全包、全取证。

## 2. 设计原则

### 2.1 证据优先

没有源/目的 IP、端口或实体上下文的流量情报不进入流量威胁展示。Incident 必须来自关联链，证据按阶段展示。

### 2.2 低噪声

平台抑制 `SURICATA TRAFFIC-ID`、文件识别类、无上下文 Chopper/PNG 等误报，优先展示可解释的威胁。

### 2.3 运行面可交付

平台服务端默认通过 HTTPS 443 和离线镜像包交付，服务端需要 Docker Compose。
政企现场采集端采用无容器静态 Linux Agent，不要求目标业务主机安装 Docker。

### 2.4 数据持久化

会话、威胁、资产、Agent 状态写入 PostgreSQL，不依赖 Redis 临时流作为唯一数据源。

### 2.5 规则可运营

规则中心提供同步、编译、热加载和回滚，避免每次变更都重启整个平台。

## 3. 核心能力

### 3.1 资产与 Agent 运维

Agent 通过 HTTPS 安装，使用管理员签发的一次性 enrollment token 注册并持久化身份。
控制中心管理能力开关、展示名、在线状态。资产运维页面同步 Agent 离线状态，并以真实上报时间计算新鲜度。

### 3.2 流量检测

流影支持两类来源：

- 本机旁路镜像：显示为“流量镜像分析”。
- 外部终端探针：显示为具体 Agent 名，例如 `dns8`。

会话持久化到 `traffic_sessions`，支持关键词查询。Nmap 风格 SYN 端口扫描在 Agent 抓包层聚合，避免事件限速丢失扫描特征。

### 3.3 运行威胁与应用威胁

运行时、日志审计和 RASP 事件进入统一遥测流，由安全引擎输出组件告警，再进入 XDR 关联。

### 3.4 XDR 攻击链

XDR 通过实体、阶段和时间窗口把多源事件关联为攻击链。前端按 `TA0043 Reconnaissance` 等阶段展示证据，每条证据带时间、来源、规则和网络/主机上下文。

### 3.5 规则中心

规则中心支持最新规则库检测、一键更新、编译预览、版本回滚和热重载。新增规则能力归入统一流量威胁规则，不拆散为多个孤立模块。

## 4. 技术架构

流影由四层组成：

1. **采集层**：`ly-agent`、本机镜像、RASP Probe。
2. **事件总线层**：Redis Streams。
3. **分析持久化层**：`ly-security-engine`、`ly-server`、PostgreSQL、ClickHouse。
4. **运营展示层**：Vue 控制台、规则中心、XDR、资产运维、威胁列表。

默认部署使用 Docker Compose，核心入口为 `ly-vis` 的 HTTPS 443。

## 5. 安装与验收

验收包由 `scripts/build-offline-release.sh` 生成，包含：

- 运行镜像归档：`images/lyflow-images.tar.gz`。
- `docker-compose.yml`。
- 初始化 SQL。
- 规则库目录。
- 一键安装脚本。

服务端目标机执行：

```bash
sudo bash scripts/install-offline.sh
```

脚本会检查 Docker、导入镜像、写入 `.env`、启动服务。验收标准包括：

- 所有核心容器启动。
- `/api/v1/health` 返回 healthy。
- 安装器生成的管理员凭据可登录并触发首次改密。
- 前端 HTTPS 页面可访问。

## 6. 安全边界

- 默认自签证书用于验收；生产建议替换正式证书。
- 默认管理员密码只用于首登，应立即修改。
- 离线包不携带 Docker 安装离线 rpm/deb；无 Docker 环境需要可访问系统软件源或提前安装。
- 规则源 URL 需要经过平台限制，避免本地文件和内网 SSRF 类风险。
- 外部 Agent 的生产网络边界应只依赖平台 HTTPS；残留的 Redis 直连兼容路径尚需收敛。
- Java RASP 仍是实验性、monitor-only 能力；响应候选目前只读，不提供自动阻断承诺。
- ClickHouse 具备分阶段迁移控制，但未经过目标现场对账和读切换前不是事件搜索权威。

## 7. 适用场景

- 内网安全态势和 XDR 轻量落地。
- 需要 Agent + 流量 + RASP + 日志审计融合的验收项目。
- 需要离线交付和现场快速部署的安全平台。
- 需要规则热更新、告警降噪和攻击链证据化的运营团队。

## 8. 结论

流影以“可解释、可持久、可安装”为核心，当前版本已经形成可验收的安装、采集、检测、关联、展示和规则运营主链路。
远端 Agent 传输收敛、现场兼容矩阵、数据读切换、响应执行和规模化部署仍属于后续生产化工作。
